Vibe Kanban から移る方法

2026年11月7日に、Vibe Kanban の告知とソースコードで確かめた内容です。Worktree Kanban は Vibe Kanban・bloop とは関係ありません。

コードは失われません。Vibe Kanban の作業は普通の git のブランチと worktree にあるので、アプリがなくても残ります。Worktree Kanban は Vibe Kanban のボードを自動では取り込めないため、このページでは、大事なものを先に保存してから、進行中の作業を手で移します。目安は、1リポジトリあたり30分ほどです。

Vibe Kanban に何が起きたか

  • 2026年4月10日に、開発元の bloop が会社の終了を告知しました。プロジェクトの README にも「sunsetting」（終了に向かっている）と書かれています。
  • 告知では、リモートサービスの提供期間は30日でした。対象は、クラウドのカンバンの Issue・コメント・プロジェクト・組織です。有料プランも終了しました。
  • ローカルのワークスペースは引き続き動くと告知され、プロジェクトはコミュニティに引き継がれました。リポジトリには2026年11月もコミットがあります。GitHub の最新リリースは、2026年4月24日の v0.1.44 です。

ローカルのワークスペースだけを使っているなら、今すぐ移る必要はありません。移行を考える理由は、開発を支える会社がなくなったことと、4月から新しいリリースが出ていないことです。

先に確かめておく違い

Worktree Kanban は完全な代わりではありません。始める前に、次の点を確かめてください。

できなくなること

  • 一部のエージェント。動かせるのは Claude Code・Codex CLI・Antigravity CLI・Gemini CLI・Cursor CLI です。GitHub Copilot・Amp・OpenCode・Droid・CCR・Qwen Code は動かせません。Antigravity・Gemini では、カード上の承認などの一部の機能が使えません。
  • 内蔵のプレビューブラウザ。開発サーバーは、いつものブラウザで開いてください。
  • 複数のリポジトリにまたがるワークスペース。タスクは1つのリポジトリに属します。リポジトリは、タブで3つまで同時に開けます。
  • Vibe Kanban 自身の MCP サーバーを使った、エージェントからのタスク管理。
  • チームのボード。ボードは1台の PC に保存されます。クラウドで共有するボードはありません。
  • Apache-2.0 のライセンス。Worktree Kanban は FSL-1.1-ALv2 で公開している source-available のソフトウェアで、競合する商用の製品やサービスには使えません。各版は、リリースから2年後に Apache 2.0 でも使えるようになります。

できるようになること

  • SSH トンネルを使った、外部サーバーなしの Mac と Windows の相互遠隔操作。
  • Pipeline と競争：フローチャートでエージェントをつなぐ、同じタスクを複数のエージェントに解かせる。
  • 大きなタスクのサブタスク分割と、タスクのスケジュール実行。

移行の6つの手順

1. 作業を git に保存する

リポジトリごとに次を実行して、Vibe Kanban の worktree とブランチを一覧にします。Vibe Kanban の設定で変えていなければ、ブランチの接頭辞は vk です。

git worktree list
git branch --list 'vk/*'

残したい worktree は、コミットしていない変更をコミットし、ブランチを push します。既定の worktree の場所は一時フォルダなので、ここが大事です。

git -C <worktree のパス> status --short
git -C <worktree のパス> add -A
git -C <worktree のパス> commit -m "WIP: move from Vibe Kanban"
git -C <worktree のパス> push -u origin HEAD

2. クラウドのデータをエクスポートする（使っていた場合）

Vibe Kanban で /export を開くと、issues.csv・projects.csv・users.csv と、選べば添付ファイルの入った zip をダウンロードできます。クラウドのサービスの提供期間は30日と告知されていたので、今は使えないかもしれません。クラウドのプロジェクトを使っていなければ、飛ばしてください。

3. ローカルのデータをバックアップする

次のフォルダを安全な場所にコピーします。データベース（db.v2.sqlite）・config.json・profiles.json が入っています。credentials.json が入っていることもあるので、コピーは人に渡さず、コミットもしないでください。

OSフォルダ
Mac~/Library/Application Support/ai.bloop.vibe-kanban
Linux~/.local/share/vibe-kanban
Windows%APPDATA%\bloop\vibe-kanban\data

4. Worktree Kanban をインストールする

Mac / Linux：

curl -fsSL https://raw.githubusercontent.com/kazuya83/worktree-kanban/main/install.sh | bash

Windows（PowerShell）：

irm https://raw.githubusercontent.com/kazuya83/worktree-kanban/main/install.ps1 | iex

Releases からダウンロードすることもできます。署名・公証がないため、初めて開くときに OS の警告が出ることがあります。インストールしたらリポジトリを開き、設定の「使うエージェント」でエージェントを選び、「ブランチと取り込み」にスクリプトを入れます。

5. 進行中の作業を移す

  • ほぼ終わっている作業：ターミナルで worktree かブランチから仕上げて、いつもどおりマージするか PR を作ります。
  • まだエージェントに任せたい作業：「ブランチと取り込み」の「ベースブランチ」を vk/... のブランチにしてから、タスクを作ります。そのブランチから worktree が作られます。マージ先の初期値も同じブランチになるので、main に直接入れるときはマージの画面で選び直してください。終わったら「ベースブランチ」を元に戻します。
  • まだ始めていない Issue：タスクを手で作ります。GitHub Issue なら、「＋ 新しいタスク」の「GitHub Issue から作成」タブを使えます。

エージェントは Vibe Kanban での会話を読めません。終わったことと残っていることを、新しいタスクに書いてください。

6. 片付ける

すべてマージか push が終わったら、古い worktree と、いらなくなったブランチを消します。git branch -d は、マージしていないブランチの削除を断ります。

git worktree remove <worktree のパス>
git branch -d vk/<ブランチ名>
git worktree prune

迷うなら、あとで構いません。しばらく両方のアプリを残しておいても問題ありません。
