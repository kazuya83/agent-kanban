Conductor から移る方法

2026年11月7日に、Conductor の告知とドキュメントで確かめた内容です。Worktree Kanban は Conductor・Meta とは関係ありません。

Conductor Cloud を使っているなら、まずデータを書き出してください。Cloud は2026年11月13日に読み取り専用になり、11月20日に終了します。終了の日から、Cloud のユーザーデータの削除が始まります。何よりも先に手順1を進めてください。

ローカルのコードは失われません。Conductor のローカルのワークスペースは普通の git の worktree とブランチなので、アプリがなくても残ります。Worktree Kanban は Conductor のワークスペースやチャットを自動では取り込めないため、このページでは、大事なものを先に保存してから、進行中の作業を手で移します。目安は、1リポジトリあたり30分ほどです。

Conductor に何が起きているか

  • 2026年11月4日に、Conductor は Meta に合流すると告知しました。新しいユーザーの登録とアプリのダウンロードはできなくなりました。今のユーザーは、無料で使い続けられます。
  • Conductor Cloud は11月13日に読み取り専用になります。古いチャットを読むこととデータの書き出しはできますが、新しいメッセージは送れません。11月20日に終了し、Cloud のユーザーデータの削除が始まります。契約中の人には返金されます。
  • ローカルの Mac アプリは当面動き、2027年の初めまで新しいモデルへの対応と重大なバグの修正が続きます。そのあとは終了に向かい、アプリの終了時にすべてのユーザーデータを削除すると告知されています。

ローカルのワークスペースだけを使っているなら、今すぐ移る必要はありません。ローカルのアプリには数か月の余裕があるので、自分のペースで移れます。Cloud を使っているなら、上の日付がすぐに関わります。

先に確かめておく違い

Worktree Kanban は完全な代わりではありません。始める前に、次の点を確かめてください。

できなくなること

  • Cloud のワークスペースとマルチプレイヤー。エージェントは自分の PC で動き、ボードは1台の PC に保存されます。クラウドのサンドボックスや共有のチャットはなく、その PC の電源が切れるとタスクも止まります。
  • OpenCode。動かせるのは Claude Code・Codex CLI・Antigravity CLI・Gemini CLI・Cursor CLI です。カード上の承認などの一部の機能は、エージェントによっては使えません。
  • iOS の Remote Control アプリ。Worktree Kanban にスマートフォンのアプリはありません。
  • Conductor の API と MCP サーバーを使った、ほかのツールからの操作。
  • リポジトリで共有する設定。スクリプトは PC ごとに保存され、.conductor/settings.toml のようなファイルでは共有できません。
  • 複数のリポジトリのディレクトリをつなぐ機能。タスクは1つのリポジトリに属します。リポジトリは、タブで3つまで同時に開けます。

できるようになること

  • Windows と Linux で使える。Conductor は macOS だけです。Worktree Kanban は Windows と Linux（x86_64）でも動き、Windows では WSL のリポジトリも扱えます。なお、遠隔操作は Mac と Windows のあいだだけです。
  • Pipeline も戻せるチェックポイント。Conductor のチェックポイントは、チャットのターンを戻します。Worktree Kanban は、エージェントが動く回の直前ごとに時点を記録し、戻すとファイル・Pipeline の進み具合・会話がそろって戻ります。戻せるのはタスクがレビューか失敗で止まっているときで、時点は1タスク100件までです。戻した操作は取り消せません。
  • Pipeline。「Codex で実装して Claude でレビューし、直すところがあれば実装に戻す」のように文章で書くと、フローチャートになります。分岐・ループ・並列のとおりに、工程ごとにエージェントが作業を引き継ぎます。
  • SSH トンネルを使った、外部サーバーなしの Mac と Windows の相互遠隔操作。
  • クラウドのサービスに頼らない。データは自分の PC に保存されます。Worktree Kanban は FSL-1.1-ALv2 で公開している source-available のソフトウェアで、競合する商用の製品やサービスには使えません。各版は、リリースから2年後に Apache 2.0 でも使えるようになります。

移行の6つの手順

1. Cloud のデータを書き出す（使っている場合）

Conductor の公式の手順で、最初に行います。Cloud を使っていなければ、飛ばしてください。

  • すべてのデータをダウンロードする：Conductor の Settings → Account → Export data を開きます。
  • Cloud のワークスペースとチャットを Mac に移す：ワークスペースを右クリックして、Transfer to local を選びます。

どちらも11月13日より前に済ませてください。告知では、それ以降に11月20日の終了までできるのは、古いチャットを読むこととデータの書き出しだけです。次へ進む前に、書き出したファイルを開けることも確かめてください。

2. 作業を git に保存する

リポジトリごとに次を実行して、Conductor の worktree を一覧にします。場所はふつう ~/conductor/workspaces/<リポジトリ>/<ワークスペース> です。

git worktree list

残したい worktree は、コミットしていない変更をコミットし、ブランチを push します。push しておくと、Windows や Linux の PC でも続きから作業できます。

git -C <worktree のパス> status --short
git -C <worktree のパス> add -A
git -C <worktree のパス> commit -m "WIP: move from Conductor"
git -C <worktree のパス> push -u origin HEAD

3. ローカルのデータをバックアップする

Conductor を終了してから、次のフォルダを安全な場所にコピーします。Setup・Archive・Run のスクリプトは、.conductor/settings.toml に入っていなければ、プロジェクトの Settings から控えておきます。ワークスペースには .env などが入っていることがあるので、コピーは人に渡さず、コミットもしないでください。

フォルダ中身
~/Library/Application Support/com.conductor.appローカルのチャットの履歴とアプリのデータ
~/conductorワークスペース
~/.claude・~/.codexClaude Code と Codex のファイル。Conductor をやめたあとも、それぞれのツールが使います

4. Worktree Kanban をインストールする

Mac / Linux：

curl -fsSL https://raw.githubusercontent.com/kazuya83/worktree-kanban/main/install.sh | bash

Windows（PowerShell）：

irm https://raw.githubusercontent.com/kazuya83/worktree-kanban/main/install.ps1 | iex

Releases からダウンロードすることもできます。署名・公証がないため、初めて開くときに OS の警告が出ることがあります。使うエージェントの CLI を入れてログインしたら、リポジトリを開き、設定の「使うエージェント」でエージェントを選びます。「ブランチと取り込み」にスクリプトを入れるときは、CONDUCTOR_ で始まる変数を、上の表の名前に置き換えてください。

5. 進行中の作業を移す

  • ほぼ終わっている作業：ターミナルで worktree かブランチから仕上げて、いつもどおりマージするか PR を作ります。
  • まだエージェントに任せたい作業：「ブランチと取り込み」の「ベースブランチ」をそのワークスペースのブランチにしてから、タスクを作ります。そのブランチから worktree が作られます。マージ先の初期値も同じブランチになるので、main に直接入れるときはマージの画面で選び直してください。終わったら「ベースブランチ」を元に戻します。
  • まだ始めていない Issue：タスクを手で作ります。GitHub・GitLab・Linear・Jira の Issue なら、「＋ 新しいタスク」の Issue のタブを使えます。

エージェントは Conductor でのチャットを読めません。終わったことと残っていることを、新しいタスクに書いてください。

6. 片付ける

すべてマージか push が終わったら、Conductor でワークスペースをアーカイブするか、自分で worktree を消します。いらなくなったブランチも消します。git branch -d は、マージしていないブランチの削除を断ります。

git worktree remove <worktree のパス>
git branch -d <ブランチ名>
git worktree prune

迷うなら、あとで構いません。Conductor はもうダウンロードできないので、移し終わるまでアプリを消さないでください。
